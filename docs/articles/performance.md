# Производительность

## Практические рекомендации

### Выбор структуры

| Случай | Тип | Почему |
|---|---|---|
| Разреженный граф | `Graph<T>` (список смежности) | O(V + E) памяти |
| Очень плотный граф | Своя реализация на матрице | O(1) проверка ребра |
| Статический | `Graph<T>` | Достаточно |

### Влияние размера

- **V ≤ 100**: любой алгоритм работает мгновенно
- **V ≤ 10⁴**: Дейкстра, BFS, DFS — миллисекунды
- **V ≤ 10⁵**: избегайте O(V²) и O(V³) алгоритмов
- **V > 10⁶**: рассмотрите собственную реализацию с оптимизациями

### Оптимизации

1. **Избегайте аллокаций в горячем цикле** — используйте `ArrayPool` для временных массивов
2. **PriorityQueue** — используйте встроенную из .NET 6+
3. **Struct-based edges** для очень больших графов (замена класса на struct)
4. **Параллелизация** — Борувка, независимые части алгоритмов
5. **Кэшируйте `Neighbors`** в локальной переменной

### Пример микрооптимизации

```csharp
// Медленно: LINQ в горячем цикле
foreach (var e in graph.Neighbors(u).Where(x => x.Weight > 0)) { ... }

// Быстро: обычный foreach
foreach (var e in graph.Neighbors(u))
{
    if (e.Weight <= 0) continue;
    // ...
}
```
