# Параллельные алгоритмы

Библиотека предоставляет **9 параллельных версий алгоритмов** для работы
на многоядерных машинах. Все они находятся в namespace
`GraphToolkit.Parallel`.

## Обзор

| Алгоритм | Ускорение | Когда использовать | Файл |
|---|---|---|---|
| Параллельный BFS | 3–5× | V > 10³ | `Parallel/ParallelBfs.cs` |
| Параллельный PageRank | 4–8× | V > 10³ | `Parallel/ParallelPageRank.cs` |
| Параллельный Флойд-Уоршелл | 2–4× | V > 100 | `Parallel/ParallelFloydWarshall.cs` |
| Параллельный Беллман-Форд | 2–3× | Большие разреженные графы | `Parallel/ParallelBellmanFord.cs` |
| Параллельные компоненты | 3–6× | V > 10⁴ | `Parallel/ParallelComponents.cs` |
| SCC (Косараю) | 2–4× | Большие ориентированные графы | `Parallel/ParallelScc.cs` |
| Параллельный Борувка | 3–5× | V > 10³ | `Parallel/ParallelBoruvka.cs` |
| Delta-stepping Дейкстра | 2–5× | Плотные графы | `Parallel/ParallelDijkstra.cs` |
| Multi-source BFS | 3–7× | Задачи «ближайший из N» | `Parallel/MultiSourceBfs.cs` |

## Общие принципы

Все параллельные алгоритмы:

- ✅ **Используют `System.Threading.Tasks.Parallel`** — не требуют внешних зависимостей
- ✅ **Автоматически используют все доступные ядра** — без настройки
- ✅ **Дают идентичный результат** последовательным версиям
- ❌ **Не гарантируют порядок обхода** (для BFS/DFS)
- ⚠️ **Теряют смысл на маленьких графах** (V < 100) — накладные расходы превышают выигрыш

## Параллельный BFS

Параллельная версия обхода в ширину использует **level-synchronous**
стратегию: все вершины одного уровня обрабатываются одновременно.

```csharp
using GraphToolkit.Parallel;

var path = ParallelBfs.FindPath(graph, "A", "F");
var distances = ParallelBfs.Distances(graph, "A");
```

### Как работает

1. Обрабатываем уровень `k` параллельно — все вершины независимы.
2. Собираем вершины уровня `k+1` в `ConcurrentBag`.
3. Переходим к следующему уровню.

### Сложность

**O((V + E) / cores)** в идеальном случае, **O(V + E)** в худшем.

### Ускорение

На разреженных графах (E ≈ 3V) — **3–5×** на 8 ядрах.
На плотных графах ускорение выше.

---

## Параллельный PageRank

PageRank идеально подходит для параллелизации: каждая итерация —
это поэлементное умножение матрицы на вектор.

```csharp
using GraphToolkit.Parallel;

var ranks = ParallelPageRank.Compute(graph, damping: 0.85, iterations: 100);
```

### Ускорение

На графах V = 10⁵ — **4–8×**.

### Когда использовать

- V > 1000
- Много итераций (> 50)
- Граф с большим числом рёбер

---

## Параллельный Флойд-Уоршелл

Внутренние циклы по `i` и `j` независимы при фиксированном `k`,
поэтому распараллеливаем цикл по `i`.

```csharp
var (dist, next, vertices) = ParallelFloydWarshall.Compute(graph);
```

### Ускорение

**2–4×** на многоядерных машинах.

### Ограничение

Используется **только для V ≤ 1000** — для больших графов
последовательный Флойд-Уоршелл всё равно слишком медленный.

---

## Параллельный Беллман-Форд

На каждой итерации релаксация рёбер независима, но требует
синхронизации. Используем **двойной буфер** и блокировку.

```csharp
var (dist, prev, hasCycle) = ParallelBellmanFord.Compute(graph, source);
```

### Ускорение

**2–3×**.

### Ограничение

Из-за блокировок contention может съесть часть ускорения на графах
с высокой плотностью.

---

## Параллельные компоненты связности

Lock-based union-find: каждый поток обрабатывает свой диапазон рёбер.

```csharp
var components = ParallelComponents.Find(graph);
```

### Ускорение

**3–6×** на больших графах (V > 10⁴).

### Особенность

Финальная группировка выполняется последовательно — это узкое место
на графах с большим числом компонент.

---

## Параллельный SCC (Косараю)

Алгоритм Косараю состоит из двух проходов DFS. Второй проход
выполняется по компонентам независимо.

```csharp
var sccs = ParallelScc.Find(graph);
```

### Ускорение

**2–4×** на больших ориентированных графах.

---

## Параллельный Борувка

На каждой итерации каждая компонента независимо выбирает минимальное
исходящее ребро — это узкое место распараллеливается.

```csharp
var mst = ParallelBoruvka.Compute(graph);
```

### Ускорение

**3–5×**.

### Особенность

Используется `ConcurrentDictionary` для параллельного выбора
минимального ребра.

---

## Delta-stepping Дейкстра

Параллельная версия Дейкстры через **delta-stepping**: вершины
разделяются на «корзины» по расстоянию. Внутри корзины релаксация
рёбер идёт параллельно.

```csharp
var (dist, prev) = ParallelDijkstra.DeltaStepping(graph, source, delta: 1.0);

// Или упрощённый вариант (delta = 1.0)
var (dist, prev) = ParallelDijkstra.Compute(graph, source);
```

### Параметр delta

- **`delta → 0`** — вырождается в обычную Дейкстру.
- **`delta → ∞`** — вырождается в Беллман-Форд.
- **`delta ≈ средний вес ребра`** — оптимально на практике.

### Ускорение

**2–5×** на плотных графах.

---

## Multi-source BFS

BFS от нескольких источников одновременно. Полезно для задач
«ближайший из N центров».

```csharp
var (distances, sources) = MultiSourceBfs.Compute(
    graph,
    new[] { "Склад1", "Склад2", "Склад3" });

foreach (var shop in new[] { "Магазин1", "Магазин2" })
    Console.WriteLine($"{shop}: до {sources[shop]} — {distances[shop]} км");
```

### Применения

- Оптимизация логистики (ближайший склад)
- Скорая помощь (ближайшая больница)
- Рекомендации (ближайший магазин с товаром)
- Сети доставки

### Ускорение

**3–7×**.

---

## Сравнение с последовательными версиями

Все параллельные алгоритмы дают **идентичный результат**
последовательным версиям (проверено юнит-тестами).

```csharp
// Результаты совпадают
var seq = PageRank.Compute(graph);
var par = ParallelPageRank.Compute(graph);

foreach (var v in graph.Vertices)
    Math.Abs(seq[v] - par[v]).Should().BeLessThan(1e-6);
```

## Когда НЕ использовать

- **V < 100** — накладные расходы превышают выигрыш
- **Один поток в системе** — параллелизм бесполезен
- **Детерминированный порядок обхода** — параллельные версии его не гарантируют
- **Маленькие графы в hot loop** — накладные расходы на `Parallel.ForEach`
