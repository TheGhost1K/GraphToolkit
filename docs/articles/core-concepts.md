# Ключевые концепции

## Тип вершины `T`

Все графы и алгоритмы параметризованы типом `T`:

```csharp
var g1 = new Graph<string>();   // вершины — строки
var g2 = new Graph<int>();      // вершины — целые
var g3 = new Graph<City>();     // вершины — пользовательский тип
```

Ограничение `where T : notnull` защищает от null-вершин.

> [!IMPORTANT]
> Тип `T` должен корректно реализовывать `Equals` и `GetHashCode`.
> Для пользовательских типов используйте `record` или переопределяйте оба метода.

## Ориентированность

```csharp
var directed = new Graph<string>(isDirected: true);
directed.AddEdge("A", "B");    // A → B (обратного ребра нет)

var undirected = new Graph<string>(isDirected: false);
undirected.AddEdge("A", "B");  // A — B (эквивалентно B — A)
```

## Веса рёбер

```csharp
graph.AddEdge("A", "B");           // вес по умолчанию = 1.0
graph.AddEdge("A", "B", 4.5);      // явный вес
graph.AddEdge("A", "B", -2);       // допустимо; не все алгоритмы поддерживают
```

> [!WARNING]
> Дейкстра и A* требуют неотрицательных весов. Для отрицательных
> используйте [Беллмана-Форда](shortest-paths.md).

## Интерфейс `IGraph<T>`

```csharp
public interface IGraph<T>
{
    bool IsDirected { get; }
    IEnumerable<T> Vertices { get; }
    IReadOnlyList<Edge<T>> Edges { get; }
    int VertexCount { get; }
    int EdgeCount { get; }
    IEnumerable<Edge<T>> Neighbors(T vertex);
}
```

Все алгоритмы принимают `IGraph<T>`, что делает их независимыми
от конкретной реализации.

### Реализации в библиотеке

| Класс | Структура | Когда использовать |
|---|---|---|
| `Graph<T>` | Список смежности | Разреженные графы (E ≪ V²) — по умолчанию |
| `AdjacencyMatrixGraph<T>` | Матрица смежности | Плотные графы, частые `HasEdge`/`GetWeight` за O(1) |

Обе реализации полностью совместимы — все алгоритмы работают с обеими:

```csharp
var matrix = new AdjacencyMatrixGraph<string>(isDirected: true);
matrix.AddEdge("A", "B", 4);
var path = Dijkstra.FindPath(matrix, "A", "B");   // работает
```

Подробнее — в статье [Матрица смежности](adjacency-matrix.md).

Вы также можете реализовать **свою** реализацию `IGraph<T>` и
использовать её со всеми алгоритмами библиотеки.

## Специализированные типы

### `Edge<T>`

Ребро с полями `From`, `To`, `Weight`. Реализует `IComparable`, `IEquatable`.

### `FlowNetwork<T>`

Сеть для задач максимального потока (Форд-Фалкерсон, Эдмондс-Карп, Диниц).

> [!WARNING]
> **Модифицируется** при работе алгоритмов — остаточные пропускные
> способности уменьшаются. Для сравнения нескольких алгоритмов
> на одних данных используйте `net.Clone()`:

```csharp
double f1 = Dinic.Compute(net.Clone(), "S", "T");
double f2 = EdmondsKarp.Compute(net.Clone(), "S", "T");
// net остался нетронутым
```

### `CostFlowNetwork<T>`

Сеть с пропускной способностью и стоимостью для задач min-cost flow
(SPFA, Дейкстра с потенциалами). Также **модифицируется** при работе
алгоритмов и поддерживает `Clone()`.

### `UnionFind<T>`

Система непересекающихся множеств с ранговой эвристикой и сжатием путей.
Используется в Краскале, Борувке и других алгоритмах.

## Идиома «нет значения» вместо `T?`

Под ограничением `where T : notnull` **нельзя** использовать `T?`
для представления «нет значения»: для value-типов `T?` — это `Nullable<T>`,
для ссылочных — просто `T`, и компилятор не даёт универсально
присвоить `null`.

Библиотека использует **явные флаги** и **отсутствие ключа в `Dictionary`**:

```csharp
// Правильно: Dictionary без ключа = нет значения
private readonly Dictionary<T, T> _parent = new();
// Есть родитель:
if (_parent.TryGetValue(v, out var p)) { /* используем p */ }
// Нет родителя — корень дерева

// Правильно: явный флаг
public T Parent(T v)
    => _parent.TryGetValue(v, out var p) ? p : default!;

public bool IsRoot(T v) => !_parent.ContainsKey(v);
```

Если пишете свои алгоритмы на generic `T` — придерживайтесь
того же принципа. Например, `EulerianPath.HasPath` возвращает
`record PathCheckResult<T>(bool Exists, T Start, T End)` с явным
флагом `Exists`.

## Модификация входа

Некоторые алгоритмы **изменяют** переданную сеть — уменьшают
остаточные пропускные способности прямых рёбер и увеличивают обратные.
Это ядро метода Форда-Фалкерсона: без мутации остаточной сети
алгоритм не сможет найти увеличивающие пути.

| Метод | Что меняет |
|---|---|
| `Dinic.Compute(net, ...)` | Остаточные пропускные способности |
| `EdmondsKarp.Compute(net, ...)` | Остаточные пропускные способности |
| `FordFulkerson.Compute(net, ...)` | Остаточные пропускные способности |
| `MinCostFlow.Spfa(costNet, ...)` | Остаточные пропускные способности и стоимости |
| `MinCostFlow.DijkstraWithPotentials(costNet, ...)` | То же |

После запуска `net.GetCapacity(u, v)` вернёт **остаток**, а не исходную
пропускную способность. Чтобы сохранить исходные данные, используйте
`net.Clone()` перед каждым запуском.

> [!NOTE]
> `Dinic.MinCut(net, s, t)` тоже модифицирует сеть, потому что
> внутри вызывает `Dinic.Compute`. Он возвращает множество вершин
> на стороне источника, а не саму сеть.

**Не изменяют вход** все остальные алгоритмы библиотеки — они работают
через read-only интерфейс `IGraph<T>`. Даже `StoerWagner` и `GomoryHu`
строят свою внутреннюю сеть и не трогают исходный граф.

## Рекомендации

1. **Вершины-значения**: используйте `int`, `string`, `Guid` или `record`.
2. **Один граф — один экземпляр**: `Graph<T>` не потокобезопасен.
3. **Не мутируйте во время обхода**.
4. **Проверяйте `null`**: методы поиска пути возвращают `null`, если путь не существует.
5. **Клонируйте сети перед экспериментами** — иначе повторный запуск
   другого алгоритма даст неверный результат.
6. **Плотные графы → `AdjacencyMatrixGraph<T>`**: проверка ребра за O(1)
   вместо O(deg(u)).
