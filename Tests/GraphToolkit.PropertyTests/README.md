# Property-based тесты

Этот проект содержит property-based тесты для GraphToolkit на базе
[FsCheck](https://fscheck.github.io/FsCheck/).

## Зачем отдельный проект

`FsCheck.Xunit` привносит собственные атрибуты (`PropertyAttribute`)
и переопределения, которые **конфликтуют** с обычными `Fact`-тестами
в одном проекте. Поэтому property-based тесты изолированы в отдельный
проект `GraphToolkit.PropertyTests`.

## Запуск

```bash
dotnet test tests/GraphToolkit.PropertyTests/GraphToolkit.PropertyTests.csproj
```

Или все тесты решения:

```bash
dotnet test
```

## Что тестируется

Property-based подход проверяет **инварианты** алгоритмов на случайных
входах, а не конкретные значения на фиксированных примерах.

- **MST**: содержит V−1 рёбер, все три алгоритма дают одинаковый вес,
  все рёбра MST присутствуют в исходном графе
- **Кратчайшие пути**: Дейкстра = Беллман-Форд, Флойд-Уоршелл = Дейкстра
  для всех пар, путь валиден
- **Топосортировка**: соблюдает порядок всех рёбер
- **BFS**: кратчайший по рёбрам, достигает те же вершины, что и DFS
- **SCC**: разбиение покрывает все вершины, каждая SCC сильно связна
- **HLD**: LCA совпадает с LCA через бинарный подъём
- **Центроид**: удаление даёт компоненты ≤ n/2
- **Транзитивное замыкание**: рефлексивно, транзитивно, содержит
  прямые рёбра

## Настройка

Число тестовых случаев задаётся через `MaxTest` в атрибуте `[Property]`.
По умолчанию:

- 100 для быстрых тестов (MST)
- 50 для средних (кратчайшие пути)
- 30 для медленных (транзитивное замыкание, LCA)

## Отладка

При падении FsCheck выводит **минимальный контрпример** — уменьшенный
вход, на котором свойство нарушается. Это главное преимущество
property-based подхода: не нужно вручную искать редкий случай.

Пример вывода:

```
Falsifiable, after 47 tests (3 shrinks) (StdGen (1234567,296543)):
Label of failing property: Edge 12->5 violates topological order
Original:
Graph<int> { V=15, E=22 }
Shrunk:
Graph<int> { V=6, E=3 }
```
